# 模型训练数据梳理文档

> 梳理足球量化分析系统的训练机制、所需数据、库内供给、预测落库与真实缺口。  
> **文档基准：2026-08-30 实测**（对照 `training_service` / `ensemble` / `config.yaml` / MySQL）。

---

## 一、模型训练机制概览

系统采用 **ELO + 泊松 + xG + 蒙特卡洛** 四模型加权融合，由 [`training_service.py`](services/training_service.py) 统一调度；预测引擎为 [`ensemble.py`](models/ensemble.py)。

| 模型 | 实现 | 作用 | 训练产物 |
| --- | --- | --- | --- |
| ELO | [`elo_model.py`](models/elo_model.py) | 球队相对实力 | `teams.elo_rating` + 内存评级表 |
| 泊松 | [`poisson_model.py`](models/poisson_model.py) | 期望进球 λ、比分概率 | `teams.attack_strength` / `defense_strength`、`leagues.avg_goals` |
| xG | [`xg_model.py`](models/xg_model.py) | 射门/射正 → 攻防 xG → λ | `teams.xg_for` / `xg_against`（有统计的球队） |
| 蒙特卡洛 | [`monte_carlo.py`](models/monte_carlo.py) | 对泊松 λ 做随机模拟精化胜平负 | 无持久参数（运行时模拟） |
| 融合 | [`ensemble.py`](models/ensemble.py) | 加权组合四模型输出 | 全局/分联赛权重 + 超参；预测时 `soft_priors` / 环境修正 |

### 1.1 训练流水线（`train_all`）

```text
完赛样本（status=finished，有比分，按日期排序）
  → ① ELO 时序更新（全局+分联赛搜 K/主场）→ teams.elo_rating
  → ② 泊松攻防 + 联赛场均 → teams.attack/defense、leagues.avg_goals
  → ③ xG（match_player_stats 射门/射正）→ teams.xg_for / xg_against
  → ④ 持久化回写 teams / leagues
  → ⑤ 融合权重 + 泊松主场 网格搜索（全局 + 分联赛）→ EMA 平滑
  → ⑥ 写入 model_versions / training_records / accuracy_trend
  → ⑦ 进程内 ensemble 立即生效；重启后从 status=current 版本加载 weights_json
```

约束：

- 并发：`is_training` 为真时拒绝再次启动
- API 用 `BackgroundTasks` 调 `train_all`；轮询进度
- 可选 `start_date` / `end_date` 过滤样本
- 无完赛数据 → `failed`，仍写洞察与建议

触发与查询（前缀均为 `/api/v1`，路由挂载为 **`/model`** 非 `/models`）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/model/train` | 启动训练（可带日期） |
| GET | `/model/train/status` | 进度与消息 |
| GET | `/model/train/insights/latest` | 最新洞察 |
| GET | `/model/train/records` | 训练记录列表 |
| GET | `/model/train/records/{id}` | 单条详情 |
| GET | `/model/` / `current` / `{version}` | 版本管理 |
| PUT | `/model/{id}/current` | 切换当前版本 |
| GET | `/model/status` | 当前版本、权重、`by_league` / `hyperparams` |

定时联动：`priority_train`（默认 12h）→ 重点联赛增量采 + 补 `match_player_stats` → `train_all`。

### 1.2 分联赛融合权重与超参

| 规则 | 说明 |
| --- | --- |
| 全局权重 | 各联赛验证尾部混合后网格搜索，作为兜底 |
| 分联赛搜索 | 完赛 ≥ `min_league_samples`（默认 **40**）独立搜权重/超参；介于 `soft_league_samples`（默认 **20**）与 min 之间仍搜索，但按 `β=n/min` 向全局混合（`league_blended`）；再低则 `global_fallback` |
| 验证集 | 各联赛时间序末尾约 20%（上限 40 场）；软混合路径验证下限 5 场 |
| 回退 | 样本不足，或分联赛准确率不如全局 → 用全局权重/超参（`global_better` / `global_fallback`） |
| 权重平滑 | `weight_smoothing`：对新网格权重做 EMA，`α = clamp(n/(n+prior_strength), min_alpha, max_alpha)` |
| 超参网格 | `elo_k` / `elo_home_advantage` / `poisson_home_advantage`（见 `config.yaml` → `ensemble.hyperparams`） |
| 预测选用 | `predict_from_db` 按 `league_id`；返回 `weight_source`、`hyperparams_used` |
| 持久化 | `model_versions.weights_json`（含 `hyperparams` + `by_league.*.hyperparams`）；启动时加载 current |

`by_league.*.source`：`league` | `league_blended` | `global_better` | `global_fallback`  
`by_league.*.hyper_source`：`league` | `global_better` | `global_fallback`

`weights_json` 目标形态（**重新训练后**应含 `hyperparams`；见第四节现状说明）：

```json
{
  "elo": 0.2, "poisson": 0.2, "xg": 0.25, "monte_carlo": 0.35,
  "global": { "elo": 0.2, "poisson": 0.2, "xg": 0.25, "monte_carlo": 0.35 },
  "hyperparams": {
    "elo_k": 32,
    "elo_home_advantage": 100,
    "poisson_home_advantage": 1.15
  },
  "by_league": {
    "EPL": {
      "weights": { "elo": 0.2, "poisson": 0.2, "xg": 0.45, "monte_carlo": 0.15 },
      "hyperparams": {
        "elo_k": 28,
        "elo_home_advantage": 100,
        "poisson_home_advantage": 1.2
      },
      "validation_accuracy": 0.425,
      "validation_matches": 40,
      "train_matches": 774,
      "source": "league",
      "hyper_source": "league"
    }
  }
}
```

配置默认权重（未训练 / 旧 payload 无 `xg`）：`elo 0.30 / poisson 0.30 / xg 0.20 / monte_carlo 0.20`。  
权重平滑默认：`enabled: true`，`prior_strength: 40`，`min_alpha: 0.20`，`max_alpha: 0.85`。  
网格搜权重时蒙特卡洛临时约 **2000** 次；线上默认 **10000**。双方均无 xG（`coverage=0`）时，线上与验证把 `xg` 权重并入泊松。

### 1.3 预测侧（非网格训练）

| 能力 | 配置 / 入口 | 说明 |
| --- | --- | --- |
| 软先验 | `soft_priors:` | 积分榜场均积分、射手榜贡献、`players` 阵容指数；默认权重 0.05 / 0.03 / 0.03 |
| 环境修正 | `environment:` | 天气/草坪/极端气温 → 修正泊松·xG·MC 的 λ；恶劣条件可写风控预警 |
| 计算落库 | `/predictions/calculate` `/batch` `/recalculate`；`/matches/{id}/prediction?recalculate=true` | 写入 `match_predictions` + `meta_json` |
| 过期统计 | `GET /predictions/stale-stats` | 未赛缺 meta / 版本滞后 |

## 二、各模型所需数据

### 2.1 ELO

**必需：** `home_team_id`、`away_team_id`、`home_goals`、`away_goals`、`match_date`  
训练结束后回写 `teams.elo_rating`。训练更新**不**把主场加成写入存量分。

### 2.2 泊松

**必需：** 同上 + `league_id`  
产出球队 `attack_strength` / `defense_strength`、联赛 `avg_goals`。  
公式：`λ = 攻击力 × 防守力 × 联赛场均进球 × 主场优势`。

### 2.3 xG

**必需：** `match_player_stats.shots` / `shots_on_target`（按场汇总到球队）+ 对应 `matches` 比分与 `league_id`  
- 联赛转化率先验：`xg_per_shot`、`xg_per_sot`（由进球/射门估计并夹紧）  
- 单场球队 xG ≈ `0.4×shots×xg_per_shot + 0.6×sot×xg_per_sot`  
- 回写 `teams.xg_for` / `xg_against`；预测时对联赛先验 shrink（`shrink_k` 默认 4）  
- `coverage`：0 / 0.5 / 1；为 0 时融合把 `xg` 并入泊松  
- **禁止**用随机 mock 射门数据训练  

配置：`config.yaml` → `xg:`。

### 2.4 蒙特卡洛

**无需训练。** 预测时用**泊松 λ**模拟（默认 10000；搜权重时临时约 2000）。xG 不直接进入 MC 路径。

### 2.5 融合 + 软先验

**训练：** 主客队、比分、`league_id`；在四维权重与超参上网格搜索。  
**预测软先验（非硬特征）：** `standings` / `top_scorers` / `players`（`(goals+0.5×assists)/appearances` 阵容指数，双方 ≥ `min_squad_players` 才启用）。

### 3.4 球员与逐场统计

- `players`：ESPN 逐场统计会补建 `PE*` 档；软先验用 `PlayerService.team_squad_index`。  
- `match_player_stats`：ESPN summary → 射门/射正/进球/助攻/犯规/黄红牌/出场分钟等。  
- **重点联赛（五大 + 欧冠）有统计场次覆盖约 92.7%**（3673/3963）；五大联赛均约 **99%+**；UCL 整体约 **25%**（正赛淘汰阶段满覆盖，资格/附加赛/圈次多为 0）。  
- UCL 补采：**跳过资格赛**；阶段优先正赛 > `playoff` > `play_in`。  
- 定时：`match_player_stats_crawl`（约 150 场/联赛）+ `priority_train`（约 100）+ `POST /crawler/matches/player-stats/backfill`（默认 250、`prefer_older`）。**不做随机 mock。**

## 五、已知缺口与建议

### 5.1 训练样本联赛策略（已落地）

- **白名单**：重点联赛（`PRIORITY_LEAGUES` + `WC`）始终入训；其余联赛完赛（含比分）≥ `soft_league_samples`（默认 20）才入训。  
- **排除**：`league_id` 为空的「未分类」、以及不足 20 场的零散联赛（如曾出现的 K1 碎片）——避免少量杯赛/竞彩未映射场次污染 ELO/权重。  
- **入库**：`_save_matches` 遇到未知 `league_id` **直接跳过**，不再落库为 `NULL`。  
- **洞察**：仅当**重点联赛**完赛 &lt; 20 时才出高优先「重点联赛完赛过少」；非重点薄样本降为 mid「已排除训练」，不再误催「补齐五大」。  
- 实测：五大 + 欧冠完赛均远超 20 场；已清理历史未分类/K1 噪声场次。

### 5.2 当前真实缺口

1. **训练滞后于统计补采**：库内射门统计远多于旧模型时 → **全量重训**；`train_all` 成功后会**自动**按新模型补齐最多约 150 场未赛 `meta_json`（亦可模型管理「一键补齐」）。
2. **未赛预测缺 `meta_json`**：存量可用 `/predictions/recalculate`；训练后自动同步仍不足时再手动补。
3. **环境字段覆盖偏低**：完赛天气/草坪曾几乎全空；`environment/backfill` 已优先重点联赛+未赛，定时 `environment_crawl` 默认约 400 场/次；看板可观测覆盖率。
4. **UCL 资格/附加赛/圈次无 ESPN 射门源**：正赛已满；资格赛属数据边界（看板标 `no_source`）。
5. **超参落库**：新训练会写入 `weights_json.hyperparams`；看板「超参落库」可核验。
6. **队名映射**：积分榜/射手榜/欧冠圈次仍依赖映射；`GET /crawler/mapping-gaps` + 模型管理「映射缺口」列出难映射队与缺场原因。
7. **竞彩赔率、轮次等**：库内可有，**未入训练特征**（产品边界内可继续仅作展示）。

### 5.3 建议动作（按优先级）

1. **P0（已落地）**：`POST /api/v1/model/train` 全量训练 → 自动写超参 → 自动 `prediction_refresh`；不足时再「一键补齐过期未赛」。
2. **P1（已落地）**：模型管理「数据质量看板」+ `GET /crawler/data-quality` / `mapping-gaps`；「补全环境字段」或调度气象任务。
3. **持续**：`player-stats/backfill` 挖历史缺场；完善 UCL 附加赛映射与队名别名；用看板监控覆盖率与训练滞后。
4. **中长期（P2 已部分落地）**：Brier/校准/walk-forward 选参、时间衰减、MC 权重上限、Token Redis、训练守护线程；后续可继续深化滚动窗口与第二统计源。

from db.database import SessionLocal
from db.models import Match
from sqlalchemy import func

db = SessionLocal()
print(
    db.query(Match.league_id, func.count(Match.id))
    .filter(Match.status == "finished", Match.home_goals.isnot(None))
    .group_by(Match.league_id)
    .all()

### 6.2 查询 xG / 球员统计覆盖

```python
from db.database import SessionLocal
from db.models import Match, MatchPlayerStat, Team
from sqlalchemy import func, distinct
from decimal import Decimal

db = SessionLocal()
print("stats rows", db.query(func.count(MatchPlayerStat.id)).scalar())
print(
    "matches with stats",
    db.query(func.count(distinct(MatchPlayerStat.match_id))).scalar(),
)
print(
    "teams xg non-default",
    db.query(func.count(Team.id))
    .filter((Team.xg_for != Decimal("1.350")) | (Team.xg_against != Decimal("1.350")))
    .scalar(),
)
db.close()
```
