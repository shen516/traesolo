# 足球纯竞技量化分析工具 — 系统功能明细说明

> 基于当前仓库**实际代码**梳理（截至 2026-09-10）。  
> 产品定位：面向数据分析员、体育研究者与足球爱好者的赛事量化分析系统。  
> **重要声明**：本工具仅供学习、研究与数据分析使用，不构成任何投注建议；UI 与文案不得引导赌博用途。  
> 权威依据：仓库代码 + 本目录文档 + `backend/模型训练数据梳理.md`。`requirements.md` 含未落地愿景，勿按需求硬改已实现架构。

## 2. 系统架构

```
浏览器 (localhost:5173)
        │  登录守卫 + 菜单/路由权限
        ▼
  Vue3 前端（侧边栏：数据分析 / 模型中心 / 系统运维 / 系统管理）
        │  Axios → /api/v1
        ▼
  FastAPI (localhost:8000)
        ├── 业务 API（认证、赛事、预测、模型、采集、RBAC…）
        ├── EnsembleModel
        │     ├── EloModel
        │     ├── PoissonModel
        │     ├── XGModel（射门/射正代理）
        │     └── MonteCarlo（泊松 λ 模拟）
        ├── CrawlerService（500 主 / ESPN 辅 + 专项源）
        ├── SchedulerService（14 类定时任务，状态持久化）
        └── Redis（可选：Token / 预测缓存 / RQ）
                │
                ▼
        MySQL: football_analytics
```

启动行为（`backend/main.py`）：

1. 建表 / `ensure_schema`，初始化基础数据（联赛、管理员、角色权限等）。
2. 启用真实采集器；按 `scheduled_tasks.register_all` 注册定时任务，并从 DB 恢复启停状态。
3. 可选初始全量采集（由环境变量控制，默认通常关闭）。
4. 从当前 `model_versions` 加载融合权重到进程内 ensemble。

## 6. 认证与权限（RBAC）

### 6.1 已实现

- bcrypt 密码哈希；登录限流；SVG 验证码（短时缓存）。
- 自定义 Token：优先 Redis，失败回退进程内存；TTL 可配。
- 表：`roles` / `permissions` / `role_permissions` / `user_roles`。
- 初始化角色（`init_db`）：`super_admin`、`operator`、`analyst`、`user`（具体权限以初始化数据为准）。
- 前端菜单与路由权限码对齐。

### 6.2 不足与风险

| 项 | 说明 |
|----|------|
| 非 JWT | `requirements.md` 写 JWT；实现为自定义 Token |
| 管理员旁路 | 超管/管理员细粒度权限检查常直接通过，误配角色风险较低但审计粒度粗 |
| 空权限兼容 | 前端对空权限数组可能放行（兼容旧会话），权限升级时需注意 |
| 无 HTTPS / AES | 开发态 HTTP；密码已 bcrypt，传输层依赖部署方 TLS |
| 默认口令 | `admin / admin123` 仅开发；生产必须修改 |
| 订阅会员 | 用户字段 + UI 展示，**无支付与功能门控** |

## 7. 预测与量化模型

### 7.1 四模型融合（已实现）

| 子模型 | 训练输入 | 预测作用 | 备注 |
|--------|----------|----------|------|
| ELO | 完赛比分时序 | 胜平负 | 可搜分联赛 K / 主场加成 |
| 泊松 | 比分 + 联赛场均 | λ、比分矩阵、胜平负 | λ = 攻×防×场均×主场优势 |
| xG | `match_player_stats` 射门/射正 | 胜平负（转 λ） | **非射门坐标级**；无统计则权重并入泊松 |
| 蒙特卡洛 | 不训练 | 用泊松 λ 模拟（默认约 10000 次） | 与泊松共线，权重有上下限约束 |

默认配置权重（`config.yaml`，训练后以 `model_versions.weights_json` 为准）：

- `elo 0.30 / poisson 0.30 / xg 0.22 / monte_carlo 0.18`

训练流水线（`training_service.train_all`）摘要：

1. 完赛样本 → ELO 时序更新  
2. 泊松攻防 + 联赛场均  
3. xG（有逐场统计时）  
4. 全局 + 分联赛网格搜权重（含软混合 / EMA 平滑 / 时间衰减）  
5. 写入 `model_versions` / `training_records` / `accuracy_trend`，进程内立即生效  

### 7.2 预测输出（已实现）

- 胜 / 平 / 负概率；主客 λ；主线/备选比分；总进球区间  
- 倾向、信心（high/mid/low）、风险等级、分析文案、比分矩阵  
- `meta_json` 扩展：分析场景、赔率分析、软先验、环境修正等  
- 按需计算、批量、过期重算、`stale-stats`；训练后可一键补齐未赛预测  

### 7.3 分析场景与赔率（已实现）

- 分析场景：`analysis_scenarios`（规则见 `DOC/预测分析场景规则.md`）  
- 竞彩赔率分析：列表卡 + 详情；赔率快照 `odds_snapshots`  
- 竞彩比分 Top3：同盘口相似赔率的历史比分分布 + 市场泊松先验，按胜平负/让球方向约束取前三；看盘对照层，不参与融合（算法与回测见 `DOC/竞彩赔率分析算法.md` 第 7 节）  
- soft_priors：积分榜 / 射手 / 阵容 / 伤病等对预测微调  
- 环境：天气/草坪可修正 λ（预测时；一般不进训练网格）  

### 7.4 模型侧不足

| 缺口 | 说明 |
|------|------|
| 位置级 xG | 需求中的射门位置/角度/类型未落地；当前为 shots/SOT 代理 |
| 蒙特卡洛独立性 | MC 依赖泊松 λ，信息增益有限（已有权重上限缓解） |
| 赛中实时推演 | Live500 主要回写比分/状态，非完整 in-play 模型 |
| 数据依赖 | 缺 `match_player_stats` 时 xG 贡献下降，需采集 SLA 保障 |

## 8. 数据采集与定时任务

任务注册**唯一数据源**：`backend/services/scheduled_tasks.py`。

### 8.1 已注册 14 类任务

| task_id | 默认间隔 | 名称 | 作用摘要 |
|---------|----------|------|----------|
| `match_crawl` | 60m | 赛事数据采集 | 500 主，空/无 URL 时 ESPN 兜底 |
| `league_crawl` | 1440m | 联赛数据采集 | liansai.500.com 目录 |
| `team_crawl` | 1440m | 球队名单采集 | 500 主，ESPN 补 id/徽标 |
| `squad_crawl` | 1440m | 球队阵容采集 | 规范联赛阵容（软先验） |
| `player_stats_crawl` | 360m | 球员进球统计 | ESPN 进球/助攻/出场 |
| `match_player_stats_crawl` | 360m | 逐场球员统计 | 射门等 → xG 原料 |
| `image_crawl` | 720m | 头像/徽标采集 | 联赛/球队/球员媒体 |
| `priority_train` | 720m | 重点联赛采集+训练 | 增量后 `train_all` |
| `standings_crawl` | 360m | 积分榜采集 | 500 主，空则 ESPN |
| `scorers_crawl` | 360m | 射手榜采集 | ESPN statistics |
| `environment_crawl` | 360m | 气象环境补全 | Open-Meteo + 环境预警 |
| `quality_alert_check` | 360m | 数据质量告警 | miss/停滞/映射缺口 → 风控 |
| `live500_crawl` | 30m | Live500 比分回写 | 只更新已有场次，不新建 |
| `injury_crawl` | 120m | 伤病采集 | ESPN → injury 预警 |

已退役：`player_crawl`（由 `squad_crawl` 承接）。

### 8.2 联赛分档（采集策略）

| 档 | 典型联赛 | 说明 |
|----|----------|------|
| core | EPL/LALIGA/BUNDES/SERIEA/LIGUE1/UCL/UEL | `priority_train` / 高 SLA；缺源不入库 |
| extended | MLS/BRA/SWE/FIN | 双源；进统计与质量看板，SLA 较低 |
| P3 双源 | NOR/K1/ECH 等 | 映射与配额按配置激活 |
| espn_only / five00_only | EC、大量 LS* 等 | 能力不齐；纯 500 不宜作 xG 重点训 |

分域策略摘要：赛程/阵容/积分 **500 主、ESPN 辅**；逐场射门/伤病/射手 **ESPN 主**（射门可有 500 fenxi 第二源）；Live 比分 **Live500**。

### 8.3 手动/流水线能力（已实现）

- P0 流水线、UEL / extended catchup、历史回补、enrich  
- 队名别名审核、mapping-gaps、质量看板  
- 长任务：`job_queue`（RQ 或线程回退）  

### 8.4 采集侧不足与风险

| 风险 | 说明 |
|------|------|
| 源站变更 | HTML 结构变化会导致采集失败，需持续维护选择器 |
| 缺源行为 | 真实采集为空时跳过入库，**不再**用 Mock 赛程/假统计兜底 |
| 任务默认停用 | 新环境需在「定时任务」页启用，否则数据不更新 |
| 合规 | 公开页爬取需遵守源站条款与频率限制 |
| 球员 stub | ESPN 缺球员时可能写 stub 保 FK，影响阵容质量 |

## 9. 风控体系

### 9.1 已实现
