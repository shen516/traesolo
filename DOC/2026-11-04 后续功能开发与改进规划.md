## 二、后续功能开发规划

### 2.1 近期（N1）：模拟预测收尾与深化

模拟预测是当前唯一在途功能，优先闭环：

1. **验收与提交**
   - 按 `模拟预测功能方案.md` §10 验收清单逐项执行：功能、奖金模式、只读性（20 次模拟后 `predictions` 表行数不变）、性能（10k 模拟 P95 < 1s）、权限矩阵；
   - 全量测试绿后，将工作区改动按逻辑拆分提交（建议：后端计算能力 / 服务与接口 / 奖金与串关 / 前端页面 / 权限与历史表）；
   - 处理 `git diff` 的 CRLF 告警：为仓库配置 `.gitattributes`（`*.py text eol=lf`、`*.vue text eol=lf`），避免行尾噪音。

2. **批量模拟与串关页面化**（方案 §12-1）
   - 后端 `parlay_calculator.py` 已具备计算能力，缺前端入口与接口编排；
   - 新增 `POST /predictions/simulate/batch`：一次选择 2~8 场未来赛事，逐场模拟后调用 `calculate_parlay` 输出 2串1~8串1 的理论奖金与命中概率；
   - 前端在 `Simulation.vue` 增加"批量模式"：多选赛事列表 + 串关结果表（过关方式 × 单注奖金 × 期望值）。

3. **模拟方案保存与回看**
   - `SimulationHistory` 表已建，补齐写入链路（当前需确认 `simulation_service` 是否已落历史，未落则按"用户主动保存"模式接入）；
   - 新增 `GET /predictions/simulations/history`（分页）与详情页，支持按赛事/时间筛选；
   - 方案对比：选两条历史记录并排展示概率与 EV 差异。

4. **敏感性分析**（方案 §12-1 的敏感性曲线）
   - 在模拟结果区增加"λ 敏感性"小图：λ ±10% 范围内主胜概率变化曲线（后端一次请求返回 5~7 个采样点，复用同种子）。

## 五、回归约束（沿用既有基线，每项改完必查）

- 测试全绿：基线 `198 passed, 1 skipped`（模拟预测测试合入后更新基线数字）。命令：

  ```bash
  cd backend
  $env:TRAESOLO_REDIS_DISABLED="1"; $env:RUN_SCHEDULER="0"; $env:TRAESOLO_DISABLE_DOCS="1"
  .\.venv\Scripts\python -X utf8 -m pytest tests -q -p no:warnings -p no:cacheprovider
  ```
