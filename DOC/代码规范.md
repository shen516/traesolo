## 2. 后端规范

### 2.1 分层与依赖方向

```
api/（HTTP 层）  →  services/（业务层）  →  db/（ORM 层）
     ↓                    ↓
  api/deps.py、authz.py（鉴权）    models/（算法引擎，被 services 调用）
```

- **依赖单向**：API 层只做参数校验、鉴权、调用 Service、组装响应；不写业务逻辑。
- **算法模型不依赖 FastAPI**：`models/` 只依赖 ORM/配置，可被脚本、任务、API 复用。

### 2.2 API 层

**新接口流程**（必须按此顺序）：

1. `backend/api/<module>.py` 新建 `APIRouter()` 并加路由；
2. `backend/api/__init__.py` 中 `include_router(xxx_router, prefix="/xxx", tags=["Xxx"])`；
3. 业务逻辑放 `services/`，不在路由函数里堆查询；
4. 前端同步在 `frontend/src/api/index.js` 增加方法。

**路由函数写法**（现状约定）：

```python
@router.get("/upcoming", dependencies=[RequireMatchRead])
async def get_upcoming_matches(
    page: int = Query(1, ge=1),
    page_size: int = Query(20, ge=1, le=100),
    db: Session = Depends(get_db),
):
    ...
    return {
        "matches": serialize(db, matches),
        "pagination": {
            "page": page, "page_size": page_size, "total": total,
            "pages": (total + page_size - 1) // page_size if page_size else 0,
        },
    }
```

- 一律 `async def` + `db: Session = Depends(get_db)`；
- 权限用 `dependencies=[RequireXxx]`（`api/authz.py` 预置别名），不要在函数体内手写鉴权；
- 写请求体用局部 `pydantic.BaseModel`（如 `LoginRequest`、`MatchCreate`）；
- 分页参数：`page`（从 1 开始）+ `page_size`（默认 20，`le=100`）；响应统一嵌套 `pagination: {page, page_size, total, pages}`；
- 错误处理：`raise HTTPException(status_code=4xx, detail="中文提示")`；业务可预期错误（如 `PredictionSkipped`）转 400 并带中文原因；
- 当前全库**未使用 `response_model=`**，返回手写 dict —— 属已知不足（见 7.1-B4）。

### 2.3 鉴权与权限

**三层机制**：

1. **中间件**（`main.py`）：除白名单（`/api/v1/auth/captcha`、`/api/v1/auth/login`、`/api/v1/health*`、`/metrics`、docs、static）外，`/api/` 下请求必须带 `Bearer Token`；
2. **Token 校验**（`api/deps.py`）：`get_current_user` 解析 Bearer → `token_store.get`（Redis 优先、内存回退）→ TTL 检查 → 加载用户并挂 `_session_roles` / `_session_permissions`；同时执行订阅懒过期 `lazy_expire_user`；
3. **细粒度权限**：
   - `require_permissions("match:manage", ...)`：任一命中即放行；`super_admin`/`admin` 角色直接放行；
   - `api/authz.py` 提供预置别名：`RequireLogin`、`RequireMatchRead`、`RequireMatchWrite`、`RequireModelManage`、`RequirePredictionCalc` 等，**新接口优先复用/扩展别名**；
   - `require_feature(...)`：订阅权益门控，被拦返回 403 + `{code: "FEATURE_LOCKED", feature, message}`，前端据此弹升级引导；
   - `assert_self_or_permission(user, target_user_id, *codes)`：本人或管理员访问用户资源。

**权限码命名**：`资源:动作`，如 `dashboard:view`、`match:upcoming`、`match:jingcai_bf`、`league:config`、`model:manage`、`user:create`、`role:assign`。种子数据见 `init_db.py`。

**CORS 顺序红线**：`CORSMiddleware` 必须在鉴权中间件**之后**注册（成为最外层），否则 401 响应无 CORS 头、前端拿不到错误信息（`main.py` 有注释说明）。

### 2.4 服务层

- **CRUD 静态类**：`services/crud/*.py`，经 `crud/__init__.py` → `services/__init__.py` 再导出；方法为 `@staticmethod`，Session 由调用方注入：

```python
class MatchService:
    @staticmethod
    def create(db: Session, data: dict):
        match = Match(**data)
        db.add(match)
        db.commit()      # 写操作在 Service 内 commit
        db.refresh(match)
        return match
```

- **写操作在 Service 内 `commit`/`refresh`**；请求路径的 Session 关闭交给 `get_db` 的 `finally`；
- **后台任务/调度/训练**自管 Session：`db = SessionLocal()` + `try/finally: db.close()`（参考 `training_service.py`）；
- 后台任务异常不抛 HTTPException：`logger.exception/error` + 返回 `{"status": "failed", ...}` 结构；
- 日志：`logger = logging.getLogger(__name__)`，参数用 `%s` 占位（非 f-string），便于延迟格式化与聚合。

### 2.5 数据访问与 Schema 演进

**当前机制（三条路径，优先级按执行顺序）**：

1. `models.Base.metadata.create_all(bind=engine)`：建缺失表（不 ALTER 已有表）；
2. `ensure_schema()`（`db/database.py`）：幂等补齐新增列 / ENUM / 索引；**禁止无条件 ALTER ENUM**（会与采集长事务争用 `matches` 元数据锁），必须先查 `information_schema` 比对差异再改，且 `SET SESSION lock_wait_timeout = 5`；
3. Alembic（`backend/alembic/`）：当前仅 `001_perf_indexes` 一条索引迁移，迁移文件需幂等。

**新增字段/表的标准动作**：

- 新表 → 只改 `db/models.py`（`create_all` 自动建）；
- 已有表加列 → `db/models.py` + `ensure_schema` 的 `_add_columns` 同步加一条；
- ENUM 扩值 → 改 ORM + `MATCH_STAGE_ENUM` 式常量 + 差异比对后再 ALTER；
- 高频查询索引 → `_ensure_performance_indexes` 或 Alembic 幂等迁移。

**索引/约束命名**（现状，见 7.1-B8 的不一致说明）：

- 索引：`idx_<表>_<列>`，如 `idx_matches_status_date_league`；
- 唯一约束：`uk_<表>_<列>` 为主流（`uk_team_alias`、`uk_fav_user_match`），少量 `uq_` 前缀历史遗留。

### 2.6 配置与环境变量

- 参数集中 `backend/config.yaml`：模型超参、融合权重、风控阈值、采集 SLA、环境修正系数、数据库 URL；
- 环境变量优先级高于配置文件的项：`DATABASE_URL`、`TRAESOLO_CORS_ORIGINS`、`TRAESOLO_DISABLE_DOCS`、`RUN_SCHEDULER`、`TRAESOLO_INITIAL_CRAWL`、`TRAESOLO_JSON_LOGS`、`TRAESOLO_LOG_LEVEL`、`DB_POOL_SIZE`、`DB_MAX_OVERFLOW`；
- **禁止**把生产密码提交进仓库；`config.yaml` 中的数据库密码仅限本地开发，生产必须 `DATABASE_URL` 注入。

### 2.7 日志与指标

- 应用日志：`backend/logs/runtime/app_YYYYMMDD.log`，默认文本格式；`TRAESOLO_JSON_LOGS=1` 切单行 JSON（`JsonLogFormatter`）；
- HTTP 访问日志由中间件统一写（`log_http_access`），业务代码不重复记访问日志；
- 指标：Prometheus `Counter/Histogram`（`traesolo_http_*`、`traesolo_predictions_total`），暴露 `GET /metrics`（白名单）。

### 2.8 测试

- 目录 `backend/tests/`，命名 `test_<领域>.py`、用例函数 `test_*`；
- `conftest.py` 提供：`client`（TestClient，session 级）、`admin_token`、`auth_headers`；会话前自动设 `RUN_SCHEDULER=0`、禁 Redis、临时 SQLite；
- 新接口至少覆盖：未登录 401、无权限 403、正常 200、参数校验 4xx。

### 2.9 Python 代码风格

- 模块 docstring 用中文简述职责（如 `"""赛事API"""`）；
- 业务字符串用 f-string；日志用 `%s` 占位；
- 新模块建议 `from __future__ import annotations` + 完整类型注解（`deps.py`、`token_store.py` 为样板）；
- 禁止 `from xxx import *`（现存例外 `services/crud/match.py:1`，见 7.1-B7）；
- 不提交密钥、本地 DB、`venv`、探针脚本产物。

## 3. 前端规范

### 3.1 组件与页面

- 一律 **Composition API + `<script setup>` + `<style scoped>`**（全仓无 Options API 页面）；
- 导入路径用别名 `@/`（`vite.config.js` 配置 `@ → ./src`）；
- 路由组件全部 `() => import('@/views/...')` 懒加载；
- 页面三态模式：`loading` → `errorMsg` → 空态/数据，错误提示用 `err?.message`（拦截器已把错误规整为 `Error(msg)`）：

```vue
<script setup>
import { computed, onMounted, ref } from 'vue'
import { matchApi } from '@/api'
import { adaptUpcomingMatch, unwrapList } from '@/utils/adapters'

async function loadData() {
  loading.value = true
  errorMsg.value = ''
  try {
    const data = await matchApi.getJingcaiBf(listParams())
    matches.value = unwrapList(data, 'matches').map(adaptUpcomingMatch)
  } catch (e) {
    errorMsg.value = e?.message || '加载失败'
  } finally {
    loading.value = false
  }
}
</script>
```

- 后端 snake_case 数据必须经 `utils/adapters.js`（`adapt*` / `unwrapList`）转换后再进模板；联赛/球队字典走 `utils/catalogCache.js`（TTL 缓存）。

### 3.2 API 访问

- **只在 `src/api/index.js` 增加/修改接口方法**，页面通过 `*Api` 对象调用，禁止散落裸 axios；
- 实例约定：`baseURL = VITE_API_BASE_URL || '/api/v1'`，`timeout: 15000`（长任务方法单独覆盖）；请求拦截自动注入 `Bearer`；响应拦截解包 `response.data`、401 清会话跳 `/login`、422 展开校验 detail；
- 按域分组导出：`authApi`、`leagueApi`、`teamApi`、`matchApi`、`predictionApi`、`userApi`、`favoriteApi`、`historyApi`、`modelApi`、`riskApi`、`standingsApi`、`scorersApi`、`trendApi`、`playerApi`、`permissionApi`、`scheduleApi` 等；
- 需要 blob 下载等绕过默认拦截的场景，在 `api/index.js` 内集中写例外并注释原因（现状见 7.2-F4）。

### 3.3 路由与权限

- `name` 用 PascalCase（`MatchList`），`path` 用 kebab-case（`/jingcai-bf`）；
- `meta`：`title`（必填，守卫拼接 `document.title`）、`icon`、`keepAlive`、`public`（仅登录页等）、`hidden`；
- 守卫顺序：设标题 → `meta.public` 放行 → 无 token 跳 `/login?redirect=` → `canAccessRoute(to.name)` 权限校验失败回首页；
- 路由权限映射集中在 `utils/permissions.js` 的 `ROUTE_PERMISSIONS`，新增页面必须登记。

### 3.4 状态管理

- Pinia 仅承载**会话状态**（`stores/user.js`：token/user/roles/permissions，与 localStorage 同步）；
- 业务列表数据不进 Pinia，放页面 `ref` + `catalogCache` 工具缓存；
- 不要在组件里直接读写 `localStorage` 的会话字段，走 store 的 actions（`login`/`logout`/`clearSession`）。

### 3.5 样式与设计令牌

- 全局暗色主题，颜色一律用 `main.css` 的 CSS 变量，**禁止另起色板/硬编码色值**：

| 类别 | 变量 |
|------|------|
| 背景 | `--bg-primary` `--bg-secondary` `--bg-card` `--bg-hover` |
| 文本 | `--text-primary` `--text-secondary` `--text-muted` |
| 强调 | `--color-gold` `--color-green` `--color-blue` `--color-red` `--color-orange` |
| 其他 | `--border-color` `--radius-sm/md/lg` `--shadow-card` `--shadow-glow` `--transition` |

- 优先复用全局类：`.card`、`.btn`/`.btn-primary`/`.btn-secondary`/`.btn-outline`、`.tag`/`.tag-low|mid|high|info`、`.flex*`、`.gap-*`、`.text-*`、`.progress-bar`；
- ECharts 颜色同样用 CSS 变量取值（`getComputedStyle` 或集中常量），不硬编码 `#00ff88` 等；
- 布局：非登录页 = `AppHeader` + `AppSidebar` + 主内容（`keepAlive`）；登录页全屏例外。

### 3.6 其他约定

- ECharts 必须经 `utils/echarts.js` 按需注册的单例引入，不直接 `import * as echarts`；
- 媒体资源 URL 走 `utils/media.js`（`/static/` + `VITE_API_ORIGIN`），图片用全局组件 `MediaImg`；
- 列表页**不默认批量算预测**（性能）；按场次按需计算/重算；
- 新功能接真实 API；采集失败跳过入库，不写假数据；
- 合规红线：文案与 UI 不得构成投注建议，禁止引导赌博用途。

## 4. 安全规范

1. 除白名单外全部接口需登录；写操作与管理接口另加 `Require*` 权限；
2. 生产环境必须设 `TRAESOLO_DISABLE_DOCS=1` 关闭在线文档、设 `TRAESOLO_CORS_ORIGINS` 收紧跨域；
3. 默认管理员 `admin/admin123` 仅供开发，生产首次部署后立即改密；
4. 数据库密码、Redis 地址等敏感配置走环境变量，不进仓库、不进文档示例之外的新文件；
5. Token TTL 86400s（`redis.token_ttl_seconds`），登出/改密即吊销。

## 5. Git 与协作

- 不提交：密钥、本地 DB（`*.db`）、`venv`/`.venv`、`node_modules`、`logs/`、探针脚本产物（`_probe_*`、`_imgs.txt` 等）；
- 临时调试脚本放 `backend/scripts/` 或用完即删，禁止散落仓库根目录（现状见 7.1-B6）；
- 不主动扩大改动范围：不删未要求的注释/代码，不顺手重构无关模块。
