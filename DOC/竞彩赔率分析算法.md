# 竞彩赔率分析算法（隐含概率 / 抽水 / 模型差）

> 配套：`backend/services/odds_analysis.py`、赛事详情/列表、模型监控「竞彩隐含 vs 模型」；比分 Top3 见第 7 节（`backend/services/jingcai_score_top3.py`）。  
> **声明**：仅供竞技分析与数据对照，不构成投注建议。

---

## 1. 数据从哪来

竞彩 SP / 让球来自 500 竞彩列表采集，**不是**模型定价输出。本模块只做换算与对照。

---

## 2. 核心公式

对三路 SP（胜 / 平 / 负）：

\[
raw_i = \frac{1}{\mathrm{SP}_i},\quad
\mathrm{overround} = \sum raw_i - 1,\quad
p_i = \frac{raw_i}{\sum raw_i}
\]

- \(p_i\)：隐含概率（归一化后和为 1）  
- overround：抽水（水分）  
- 市场倾向：\(p\) 最大的一侧（主/平/客）

同样算法分别用于：

- `odds_nspf_*`（不让球）→ 主路径  
- `odds_spf_*`（让球盘）→ 辅路径  

---

## 3. 与模型对照

\[
\Delta_i = p_i^{\mathrm{market}} - p_i^{\mathrm{model}}
\]

| |\Delta|max | 等级 |
|---------|------|
| &lt; 6pt | low |
| 6–12pt | mid |
| ≥ 12pt | high |

另记：市场倾向是否与模型倾向一致（`agree_tendency`）。

## 7. 比分 Top3：历史相似盘口比分分布（2026-10）

| 项 | 位置 |
|----|------|
| 算法 | `backend/services/jingcai_score_top3.py` |
| 配置 | `backend/config.yaml` → `jingcai_score_top3` |
| 调参 | `backend/scripts/tune_score_top3.py` |
| 测试 | `backend/tests/test_jingcai_score_top3.py` |
| 前端 | `frontend/src/components/ScoreTop3Panel.vue`（胜平负/让球页、比分页展开行） |

定位：看盘对照层，与 `odds_heuristics` 同级；**不参与融合训练，不替换主预测结论**。

### 7.1 样本口径

- **已完赛竞彩场次**：`status = finished` 且 `result` 非空。`home_goals` / `away_goals` 默认值为 0，不能只凭比分判断是否完赛。
- 必须有让球盘口 `handicap` 和完整的让球 SP；胜平负 SP 可以缺失（只开让球的场次），缺失时这类样本只参与单玩法相似度。
- **赔率取值**：优先取 `odds_snapshots` 中开赛前最后一帧（让球 SP 完整）；没有快照时用 `matches` 行上的值（赛果回写会覆盖为收盘 SP）。可用 `no_snapshot_weight` 给无快照样本降权，默认 1.0 不降权。
- **不穿越**：只用开赛时间早于目标场次至少 3 小时的样本，因此已完赛场次也能按赛前视角复盘。
- 回溯 `lookback_days`（默认 540 天）；样本库在进程内缓存 `cache_ttl_seconds`（默认 600 秒），赛果回写成功后由采集侧主动清空。

### 7.2 算法

**① 特征**：胜平负隐含概率 \((p_H,p_D,p_A)\) 与让球隐含概率 \((r_H,r_D,r_A)\)，公式见第 2 节。

**② 相似样本（核加权 kNN）**：盘口相同为硬约束；在概率空间取欧氏距离最近的 `k` 场，按高斯核加权

\[
w_i = e^{-d_i^2 / 2h^2}\times \text{同联赛加成}\times 0.5^{\,\text{天数}/\text{半衰期}}
\]

**③ 市场泊松先验**：在 \(\lambda \in [0.2, 3.5]\) 网格上反解 \((\lambda_{主}, \lambda_{客})\)，使泊松模型的胜平负、让球概率与市场隐含概率的平方误差最小，再生成比分矩阵 \(P_{poisson}\)。

**③b 比分 SP 先验**（`bf_prior_weight`，默认 0）：只用开赛前最后一帧、且 31 个键都是正数的比分 SP，按 \(1/\mathrm{SP}\) 去水得到 \(P_{比分}\)。缺帧、缺格、非正数则这一路权重为 0。「胜其它 / 平其它 / 负其它」保持为键，不拆成网格里没有报价的具体比分。

**③c 模型 λ 先验**（`model_prior_weight`，默认 0）：用开赛前预测的 \((\lambda_{主},\lambda_{客})\) 调用现成的 10×10 `poisson_grid`。不读落库的 5×5 `score_matrix`。没有赛前 λ 时这一路权重为 0。

\[
P_{prior}=(1-w_{bf}-w_{model})\,P_{poisson}+w_{bf}\,P_{比分}+w_{model}\,P_{模型λ}
\]

两路权重之和超过 1 时按比例压到 1。方向截断在混合之后。两个权重都是 0 时与只使用泊松先验相同。

在有赛前 λ 的场次上，把 \(w_{model}\) 设为 1 的不约束 Top3 没有高于同批当前结果时，权重保持 0。模型方向按钮仍不开放。

**④ 平滑**：

\[
P_{hist}(s) = \frac{\sum_i w_i\,\mathbb{1}[score_i = s] + \alpha\,P_{prior}(s)}{\sum_i w_i + \alpha}
\]

样本越少，结果越接近市场先验。

**⑤ 逐级放宽**：“相似样本当量”定义为核权重之和 \(\sum e^{-d^2/2h^2}\)，相当于“完全相似的样本数”。低于 `min_effective_samples` 时进入下一级：

| 级别 | 依据 |
|------|------|
| 0 | 同盘口 · 胜平负与让球赔率相似 |
| 1 | 同盘口 · 单一玩法赔率相似（优先让球） |
| 2 | 同盘口全部样本（不计距离） |
| 3 | 市场泊松先验（样本不足） |

**⑥ 方向约束**：设 \(d = 主队进球 - 客队进球\)，盘口 \(hc\)（-1 表示主队让 1 球）：

- 胜平负：\(d>0\) 胜，\(d=0\) 平，\(d<0\) 负；
- 让球：\(d+hc>0\) 让胜，\(=0\) 让平，\(<0\) 让负。

以 \(hc=-1\) 为例：

| 组合 | 净胜球 | 典型比分 |
|------|--------|----------|
| 胜 + 让胜 | \(d \ge 2\) | 2:0、3:1、3:0 |
| 胜 + 让平 | \(d = 1\) | 1:0、2:1、3:2 |
| 平 + 让负 | \(d = 0\) | 0:0、1:1、2:2 |
| 负 + 让负 | \(d < 0\) | 0:1、1:2、0:2 |
| 负 + 让胜 / 胜 + 让负 等 | — | 不可能同时成立 |

**⑦ 汇总取前三**：概率在 10×10 进球网格上计算（单队 ≥9 球归入最后一格），先按方向截断并重新归一化，再汇总到竞彩比分的 31 个键（`1:0` … `胜其它`/`平其它`/`负其它`），取前三。方向按实际比分判定，“其它”类不会出现方向歧义。返回的 `prob` 是**该方向内的条件概率**，`prob_unconditional` 是不约束时的概率。

**方向来源**（`nspf` / `spf` 参数）：

| 取值 | 含义 | 冲突处理 |
|------|------|----------|
| `any`（默认） | 不约束 | — |
| `H` / `D` / `A` | 用户手选 | 不放宽；组合不可能时返回 `available=false` 与原因 |
| `auto` | 看盘启发式倾向（`odds_heuristics` 的 `lean`） | 与其它方向冲突时自动放宽，记入 `constraint.relaxed` |
| `model` | 开赛前最后一条模型预测（`match_predictions.created_at <= 开赛时间`）：胜平负取融合概率最大项；让球取预测 λ 泊松网格在该胜平负方向内概率最大的让球结果，两者必然相容 | 无赛前预测时该维度不约束，返回 `model_available=false`；冲突时与 `auto` 一样放宽 |

返回中的 `constraint.source` 标明每个维度的方向来源（`user` / `heuristic` / `model` / `none`），`model` 字段给出模型方向本身，便于对照。

`model` 目前只在接口和回测中提供，**前端不提供“模型倾向”按钮**：回测中它低于不约束（见 7.4），按“回测优于不约束才在前端开放”的规则暂不开放。

### 7.3 接口与权益

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/v1/matches/jingcai/score-top3?match_ids=&nspf=&spf=` | `RequireMatchRead` | 逗号分隔赛事 ID，单次最多 `max_batch`（默认 50）场；按需请求，列表页不批量计算 |
| GET | `/api/v1/matches/jingcai/score-top3/backtest?days=` | `model:manage` | 滚动回测报告 |

- 权益与比分 SP 相同（`jingcai:bf`）：免费版只返回第 1 个比分，并标记 `top3_locked`（`mask_score_top3_list`）。
- 已完赛场次额外返回 `actual_score` 与 `hit`（是否命中 Top3）。
- 前端：胜平负/让球页、比分页展开某行时显示面板；比分页同时高亮 Top3 对应的比分格子。

### 7.4 回测与调参

`backtest()` 按开赛时间滚动，每场只用之前已完赛的样本：

- `modes.none`：不约束方向；
- `modes.auto`：看盘启发式方向；
- `modes.model`：模型赛前预测方向，只统计有赛前预测的场次；`model_subset` 给出同一子集上不约束的命中率，用于公平对比；
- `direction_accuracy`：`auto` / `model` 的胜平负、让球、两者都对的方向准确率；
- `modes.oracle`：真实胜平负 + 让球方向，代表方向判断正确时的命中上限；
- `baselines.prior` / `prior_oracle`：只用市场泊松先验（不约束 / 真实方向）；
- `baselines.heuristic`：看盘启发式写死的比分；
- `bf_subset`：有完整赛前比分快照的场次上，纯泊松先验（`prior`）与纯比分 SP 先验（`bf_prior`），都不混历史。后者 Top3 没有高于前者时，`bf_prior_weight` 保持 0；
- `model_lambda_subset`：有赛前 λ 的场次上，不约束的当前结果（`none`）与模型 λ 权重为 1 的不约束结果（`model_prior`）。后者没有高于前者时，`model_prior_weight` 保持 0。

2026-10 首次回测（最近 60 天，346 场，样本库 8/29 起）：

| 条件 | Top1 | Top3 |
|------|------|------|
| 不约束 | 12.1% | 32.4% |
| 看盘启发式方向 | 13.9% | 25.1% |
| 真实方向（上限） | 36.4% | 80.9% |
| 基线：先验不约束 | 13.9% | 31.8% |
| 基线：先验 + 真实方向 | 35.6% | 81.2% |
| 基线：启发式写死比分 | 9.1% | 18.5% |

结论：

- 方向判断是否正确决定命中率（约 32% → 约 81%），因此方向由用户选择，默认不约束。
- 看盘启发式方向反而降低命中率，只作为可选项保留。
- 模型方向（有赛前预测的 158 场）：Top3 17.1%，同子集不约束为 32.3%；胜平负与让球方向都对的比例为 29.1%（启发式为 25.1%）。方向准确率不足以弥补截断损失，所以前端暂不开放。

回测结果在后台“模型管理 → 监控诊断 → 比分 Top3 滚动回测”卡片中查看（`ScoreTop3BacktestCard.vue`）：

- 切到该标签时才请求，可选 30 / 60 / 90 / 180 天，命中率低于不约束的行标红；
- 卡片内含按盘口拆分、依据级别分布和当前参数。
- 样本仅约 350 场时，历史统计与市场先验基本持平，所以当前参数偏向先验（`smoothing_alpha=80`、`min_effective_samples=25`）。

调参步骤：

1. `cd backend && python scripts/tune_score_top3.py 60`（参数为回测天数）。
2. 脚本先用 60 天和 90 天的子集回测**分别**决定 `bf_prior_weight`、`model_prior_weight`（只取 0 或 1）。任一窗口没有高于对照，该权重保持 0。这两项不和网格相乘。
3. 网格只搜 `k`、`bandwidth`、`smoothing_alpha`、`min_effective_samples`，权重锁定为上一步的结果，**不自动写回**。真实方向 Top3 低于「先验 + 真实方向」的组合剔除；其余先按「不约束 Top3 − 先验不约束 Top3」降序，再按真实方向 Top3 降序。
4. 两路权重都是 1 时，才建议把 `smoothing_alpha` 降到当前值以下；否则这些行标为「暂不下调 α」。建议为「可考虑」才手动写回 `config.yaml → jingcai_score_top3`，重启后再用 60 天和 90 天卡片复核。任一窗口的不约束 Top3 掉到泊松先验以下，把新权重改回 0。
5. `lookback_days`、`same_league_boost`、`no_snapshot_weight`、`recommend_count` 不在这次搜索里。历史统计明显优于先验后，再逐步调低 `smoothing_alpha`（80 → 40 → 20）。

### 7.5 边界

- 文案统一为“历史相似盘口比分分布 / 对照”，不使用“推荐投注”等表述。
- 小盘口（±2 及以上）样本少，多数场次会退到市场先验；界面会显示依据级别与相似样本当量。
- 比分 SP 只读 `odds_snapshots.odds_bf_json` 里开赛前的最后一帧，不读会被赛果覆盖的 `matches.odds_bf_json`。当前 `bf_prior_weight: 0`、`model_prior_weight: 0`，推荐与改前一致。模型 λ 用 10×10 泊松网格，不读 5×5 `score_matrix`。
