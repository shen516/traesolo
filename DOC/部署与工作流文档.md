## 3. 前端部署



### 3.1 开发模式

```bash
cd frontend
npm install          # 安装依赖
npm run dev          # 启动开发服务器 → http://localhost:5173
```



### 3.2 生产构建

```bash
cd frontend
npm run build        # 构建产物输出到 frontend/dist/
npm run preview      # 本地预览构建结果
```



### 3.3 前端配置说明

`vite.config.js` 关键配置：

```javascript
{
  server: {
    port: 5173,        // 开发服务器端口
    open: true          // 启动时自动打开浏览器
  },
  resolve: {
    alias: {
      '@': './src'      // 路径别名，import '@/views/...' → src/views/...
    }
  }
}
```

`nginx.conf` 生产环境配置：

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;

    # 前端路由 (Vue Router history 模式)
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理到后端模型服务
    location /api/ {
        proxy_pass http://model-api:8000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 静态资源缓存 30 天
    location ~* \.(js|css|png|jpg|svg|ico|woff2?)$ {
        expires 30d;
    }
}
```

## 4. 后端部署



### 4.1 本地开发部署

```bash
cd backend

# 1. 创建虚拟环境
python -m venv venv

# 2. 激活虚拟环境
# Windows:
venv\Scripts\activate
# Linux/Mac:
source venv/bin/activate

# 3. 安装依赖
pip install -r requirements.txt

# 4. 启动 API 服务
python main.py        # → http://localhost:8000

# 或使用 uvicorn 启动（支持热重载）
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```



### 4.2 验证服务

```bash
# 健康检查
curl http://localhost:8000/

# 模型状态
curl http://localhost:8000/api/v1/model/status

# 预测接口
curl -X POST http://localhost:8000/api/v1/predict \
  -H "Content-Type: application/json" \
  -d '{"home_team":"MCI","away_team":"ARS"}'
```



### 4.3 后端依赖清单

`requirements.txt`：

```
fastapi==0.111.0       # Web 框架
uvicorn==0.30.0        # ASGI 服务器
numpy==1.26.4          # 数值计算
scipy==1.13.0          # 泊松分布计算
scikit-learn==1.5.0    # xG 模型（逻辑回归）
pyyaml==6.0.1          # 配置文件解析
joblib==1.4.2          # 模型持久化
```



### 4.4 跨域配置

后端 `main.py` 已配置 CORS，允许前端跨域访问：

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173", "http://127.0.0.1:5173"],
    allow_methods=["*"],
    allow_headers=["*"],
)
```

生产环境中前端通过 Nginx 反向代理访问 API，无需 CORS。

## 5. Docker 一键部署

> **线上若 MariaDB/Redis 在宿主机**：用 `docker-compose.host.yml` + 根目录 `.env` + 宿主机 Nginx（`frontend/nginx.host-dist.conf`）。  
> 首次部署、**后续更新应用**、故障对照见 `DOC/阿里云Linux部署环境与命令.md` §3.5。

### 5.0 宿主机库模式（推荐线上）

```bash
cd /u01/app/traesolo
cp .env.production.example .env && chmod 600 .env   # 首次：编辑 DATABASE_URL / ADMIN_PASSWORD
docker compose -f docker-compose.host.yml --env-file .env up -d --build

# 后续仅后端代码：
git pull
docker compose -f docker-compose.host.yml --env-file .env restart model-api rq-worker

# 后续依赖变更（requirements.txt）：
docker compose -f docker-compose.host.yml --env-file .env up -d --build --force-recreate model-api rq-worker

# 后续前端：
cd frontend && npm ci && npm run build
sudo nginx -t && sudo systemctl reload nginx
```

### 5.1 启动全部服务（全容器）

```bash
# 在项目根目录执行
docker-compose up -d
```

启动后各服务端口：


| 服务           | 容器名                | 端口   | 说明                |
| ------------ | ------------------ | ---- | ----------------- |
| 前端 (Nginx)   | football-frontend  | 80   | Vue 静态文件 + API 代理 |
| 后端 (FastAPI) | football-model-api | 8000 | 模型预测 API          |
| Redis        | football-redis     | 6379 | 缓存（可选）            |




### 5.2 访问方式

```
前端页面：  http://localhost
API 接口：  http://localhost/api/v1/predict
健康检查：  http://localhost/api/v1/model/status
```



### 5.3 Docker 编排文件

`docker-compose.yml`：

```yaml
services:
  model-api:                    # 后端模型服务
    build: ./backend
    ports: ["8000:8000"]
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request; ..."]
      interval: 30s
      retries: 3
    restart: always

  frontend:                     # 前端 Nginx 服务
    build:
      context: ./frontend
      dockerfile: Dockerfile
    ports: ["80:80"]
    depends_on:
      model-api:
        condition: service_healthy   # 等后端健康检查通过再启动
    restart: always

  redis:                         # 缓存服务
    image: redis:7-alpine
    ports: ["6379:6379"]
    restart: always
```



### 5.4 常用 Docker 命令

```bash
# 启动全部服务（后台）
```

## 6. 模型配置详解



### 6.1 配置文件位置

```
backend/config.yaml
```



### 6.2 完整配置说明

```yaml
# ===== 泊松模型配置 =====
poisson:
  max_goals: 10              # 比分矩阵最大进球数 (生成 10×10 矩阵)
  home_advantage: 1.15       # 主场优势系数 (λ 乘以 1.15)
  league_avg_goals:          # 各联赛场均进球数 (用于计算攻防强度)
    EPL: 2.85                # 英超
    LALIGA: 2.50             # 西甲
    BUNDES: 3.10             # 德甲
    SERIEA: 2.60             # 意甲
    LIGUE1: 2.70             # 法甲
    UCL: 2.80                # 欧冠

# ===== ELO 评级配置 =====
elo:
  k_factor: 32               # K 因子，控制评级变化幅度
  home_advantage: 100        # 主场优势加成 (ELO 分)
  initial_rating: 1500       # 新球队初始 ELO 评级

# ===== 蒙特卡洛模拟配置 =====
monte_carlo:
  simulations: 10000         # 模拟次数，越大越精确
  parallel_workers: 4        # 并行计算进程数

# ===== 模型融合权重 =====
ensemble:
  weights:
    elo: 0.30                # ELO 模型权重
    xg: 0.40                 # xG 模型权重
    poisson: 0.30            # 泊松模型权重
  # 三者权重之和必须为 1.0

# ===== 风控配置 =====
risk_control:
  min_confidence: 0.40       # 最低信心阈值，低于此值标记高风险
  max_uncertainty: 0.35      # 胜平负最大概率差阈值
```



### 6.3 修改配置后的生效方式


| 部署方式   | 生效方法                               |
| ------ | ---------------------------------- |
| 本地开发   | 重启 `python main.py`                |
| Docker | `docker-compose restart model-api` |
| 生产环境   | 重新构建镜像并推送                          |




### 6.4 各模型作用与参数调优建议


| 模型     | 作用            | 核心参数                                 | 调优建议                    |
| ------ | ------------- | ------------------------------------ | ----------------------- |
| 泊松模型   | 计算 λ 值和比分概率矩阵 | `home_advantage`, `league_avg_goals` | 主场优势 1.10~1.20 为合理区间    |
| ELO 模型 | 评估球队相对实力      | `k_factor`, `home_advantage`         | K 值 16~40，K 越大近期比赛影响越大  |
| 蒙特卡洛   | 模拟精化预测结果      | `simulations`                        | 10000 次足够，50000 次精度提升有限 |
| 融合引擎   | 加权组合三模型       | `weights`                            | 根据各模型回测准确率动态调整          |

### 8.2 预测流程（单场比赛）

```
用户选择比赛 (主队 vs 客队)
        │
        ▼
┌─────────────────────────────────────┐
│  第1步: 泊松模型                     │
│                                     │
│  攻防参数 → 计算预期进球 λ           │
│  λ_home = 攻击力 × 防守力 × 联赛均值 × 主场优势 │
│  λ_away = 攻击力 × 防守力 × 联赛均值           │
│                                     │
│  λ → 泊松分布公式 → 比分概率矩阵 (10×10) │
│  矩阵 → 汇总胜平负概率                │
└──────────────┬──────────────────────┘
               ▼
┌─────────────────────────────────────┐
│  第2步: ELO 评级模型                  │
│                                     │
│  主队 ELO + 主场加成 vs 客队 ELO     │
│  → 预期得分 → 胜平负概率             │
│  ELO 差越大 → 平局概率越低           │
└──────────────┬──────────────────────┘
               ▼
┌─────────────────────────────────────┐
│  第3步: 蒙特卡洛模拟                  │
│                                     │
│  用 λ 生成泊松随机数 × 10000 次      │
│  统计: 胜/平/负次数                  │
│  统计: 各比分出现频率 → Top5 比分    │
│  统计: 总进球均值和标准差            │
└──────────────┬──────────────────────┘
               ▼
┌─────────────────────────────────────┐
│  第4步: 加权融合                     │
│                                     │
│  最终胜率 = 0.3×泊松胜率 + 0.3×ELO胜率 │
│  最终负率 = 0.3×泊松负率 + 0.3×ELO负率 │
│  最终平率 = 1 - 胜率 - 负率          │
└──────────────┬──────────────────────┘
               ▼
┌─────────────────────────────────────┐
│  第5步: 结果生成                     │
│                                     │
│  · 胜平负概率                        │
│  · 主线比分 (概率最高)               │
│  · 备选剧本 (Top3 次高概率)          │
│  · 总进球区间                        │
│  · 信心等级 (high/mid/low)           │
│  · 风险等级 (low/mid/high)           │
│  · 倾向描述                          │
```

## 9. 常见问题



### Q1: 前端启动报错 "Cannot find module"

```bash
cd frontend
rm -rf node_modules
npm install
npm run dev
```



### Q2: 后端启动报错 "No module named fastapi"

```bash
cd backend
# 确保已激活虚拟环境
venv\Scripts\activate        # Windows
source venv/bin/activate     # Linux/Mac

# 重新安装依赖
pip install -r requirements.txt
```



### Q3: Docker 构建失败

```bash
# 清理缓存重新构建
docker-compose build --no-cache

# 查看构建日志
docker-compose build --progress=plain
```



### Q4: 前端无法访问后端 API

检查以下几点：

1. 后端服务是否启动：`curl http://localhost:8000/`
2. CORS 配置是否正确（开发模式）
3. Nginx 代理配置是否正确（生产模式）
4. 防火墙是否放行 8000 端口



### Q5: 模型预测结果不准确

```yaml
# 调整 config.yaml 中的权重
ensemble:
  weights:
    elo: 0.25        # 降低 ELO 权重
    xg: 0.50          # 提高 xG 权重
    poisson: 0.25     # 降低泊松权重

# 增加蒙特卡洛模拟次数
monte_carlo:
  simulations: 50000  # 从 10000 提升到 50000
```

修改后重启后端服务生效。

### Q6: 如何切换前端从 Mock 数据到真实 API

在前端代码中将 `import { matches } from '@/mock/data'` 替换为 API 调用：

```javascript
// 替换前 (Mock)
import { matches } from '@/mock/data'

// 替换后 (API)
const response = await fetch('/api/v1/predict', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ home_team: 'MCI', away_team: 'ARS' })
})
const result = await response.json()
```

API 返回的数据结构与 Mock 数据完全一致，无需修改渲染逻辑。
