### 3.2 `trend` 读接口权限 ✅

原实现 `backend/api/trend.py:11`：

```python
router = APIRouter(dependencies=[RequireModelManage])
```

`backend/api/authz.py:18` 的 `RequireModelManage = Depends(require_permissions("model:manage"))`。结果是三个 GET（`/`、`/version/{version}`、`/recent/{days}`）**从"只要求登录"升格成了"要求 model:manage"**，普通持有 `dashboard:view` 的用户读不到准确率趋势——而原始问题是元数据对普通用户"可见"（过宽），目标是收敛到合理读权限，不是收敛到管理权限。

**已修**：router 级留空，读写各自标注（与 `api/models.py:27,32,159,312` 已有模式一致）：

```python
router = APIRouter()

@router.get("/", dependencies=[RequireModelRead])          # model:manage 或 dashboard:view
@router.get("/version/{version}", dependencies=[RequireModelRead])
@router.get("/recent/{days}", dependencies=[RequireModelRead])
@router.post("/", dependencies=[RequireModelManage])       # 仅 model:manage
@router.delete("/{trend_id}", dependencies=[RequireModelManage])
```

关键约束：**router 级不能挂 `APIRouter(dependencies=[...])`**。FastAPI 中函数级 `dependencies` 会与 router 级叠加（两者都需满足），那样读接口就会被逼成 `model:manage`。该契约已写入模块 docstring。

**回归用例**：新增 `backend/tests/test_trend_permissions.py`（5 例）——`dashboard:view` 用户能读三个 GET、只持 `profile:view` 的 viewer 仍 403、`dashboard:view` 用户 POST/DELETE 403、超管读不被误伤。
已用"把 router 级换回 `dependencies=[RequireModelManage]`"做对抗验证：`test_trend_reads_require_only_dashboard_view` 随即红掉（`403` ≠ `200`），证明该用例确实有区分能力而非恒绿。
